# Decisions

Product-level revisions live in `docs/BLUEPRINT.md` section 0. This log records implementation choices, why they were made, and what would reopen them.

| # | Date | Decision | Why | Revisit when |
|---|---|---|---|---|
| D1 | 2026-09-13 | Build in the `parking_personal` workspace rather than `portfolio-recreations/parking-platform` | The user opened this workspace for the project; the blueprint allows the user's actual workspace | The portfolio is reorganised |
| D2 | 2026-09-13 | Vite + React SPA instead of Next.js (user decision) | Private session-auth app, no SEO; no Node runtime; clean offline/PWA base | Public pages need server rendering for SEO |
| D3 | 2026-09-13 | Target both PC browsers and Android POS (user decision) | Printer path chosen at runtime: `window.print` or a Capacitor plugin | A single device class is chosen |
| D4 | 2026-09-13 | Offline scope is cash walk-in facts only (user decision) | Facts replay safely; claims on capacity or provider money do not | Operators need offline reservations or passes |
| D5 | 2026-09-13 | TypeScript 5.9, not 7.0 | `openapi-typescript` 7.13 declares a `typescript ^5.x` peer | `openapi-typescript` supports TypeScript 7 |
| D6 | 2026-09-13 | Python pinned to 3.12 with `backend/.python-version` | uv defaulted to 3.14; the blueprint and Docker image use 3.12 | Moving the Django LTS line |
| D7 | 2026-09-13 | React Router 8 in data-router library mode | Router was unspecified after dropping Next.js; library mode keeps the build fully static | Typed search params or file routes become worth a new dependency |
| D8 | 2026-09-13 | Biome for TypeScript/CSS/JSON, Ruff for Python | One binary each for lint and format | A needed rule exists only in ESLint |
| D9 | 2026-09-13 | camelCase wire format via `djangorestframework-camel-case` plus the drf-spectacular camelize hook; `config.api.envelope_schema_hook` mirrors the `{data}` envelope in OpenAPI | Generated TypeScript types must describe real responses | The envelope or casing changes |
| D10 | 2026-09-13 | Ports 4330 (gateway/Vite), 8330 (native Django), 54330 (Postgres); images `postgres:17.11-alpine`, `caddy:2.11.4-alpine` | Host ports 5432 and 8000 were already in use on the original machine | Port conflicts elsewhere |
| D11 | 2026-09-13 | Tests read only `TEST_DATABASE_URL`, pin `TEST.NAME`, and refuse a database matching `DATABASE_URL` | Blueprint: never point tests at an inherited database | — |
| D12 | 2026-09-13 | Signed-out API calls return `403 NOT_AUTHENTICATED`; wrong credentials return `401 INVALID_CREDENTIALS` | DRF session auth sends no `WWW-Authenticate`, so it coerces 401 to 403; the SPA branches on `code` | Token authentication is added |
| D13 | 2026-09-13 | Login and registration enforce CSRF explicitly (`CsrfProtectedMixin`) | DRF skips CSRF for anonymous requests, which would allow login CSRF | — |
| D14 | 2026-09-13 | `config.api` never imports `rest_framework.views` at module level | APIView's class body loads renderer settings that point back into `config.api` (circular import found during setup) | — |
| D15 | 2026-09-13 | Staff directory UI at `/settings/staff`; `/members` stays reserved for parking passes | Removes the staff-membership vs member-pass naming clash in routes | — |
| D16 | 2026-09-13 | API container runs migrations on start | This edition runs one API replica | More than one replica: move to a release job |
| D17 | 2026-09-13 | Fonts self-hosted from `@fontsource` packages (SIL OFL, licences ship in the packages) | Blueprint: self-host fonts, no external font CDN | — |
| D18 | 2026-09-13 | Money displays with `en-IN` lakh grouping and a U+2212 minus sign | Nepali grouping convention; screen readers announce "minus" | Locale requirements change |
| D20 | 2026-09-14 | Tariff routes nest under the location (`/locations/:id/tariffs`) instead of the blueprint's flat `/tariffs` | Same scoping as bays: one organisation-scoped location lookup gives the 404, with no query-parameter validation | Organisation-wide tariff reporting needs a flat list |
| D21 | 2026-09-14 | Tariff version status (`SCHEDULED`/`CURRENT`/`SUPERSEDED`) is derived in the list query from `clock.now()`, never stored | A stored status would need a job to flip it at the effective time, and versions are immutable | — |
| D22 | 2026-09-14 | The calculator counts whole elapsed seconds (floor) and clamps a discount above the base to the base; `fixtures/tariff-vectors.json` pins both | Browsers have millisecond and Python microsecond precision; flooring gives both the same answer and never charges for a fraction of a second. The blueprint says discounts are "capped at the base" | Authorised discounts above the charge must be rejected instead |
| D23 | 2026-09-14 | `seed_demo` lives in `config` (an installed app with no models) and needs `DEMO_PASSWORD`, which setup generates separately from the server secrets | Seeding spans modules, and placing it inside one would make that module depend on the others. The demo password is typed at sign-in and must never equal the database password | A dedicated demo app arrives with `demo:reset` |
| D24 | 2026-09-14 | The concurrent-entry test (P02) moves from M1 to M2 | M1 has no parking sessions; a bay-lock race test cannot fail without the partial unique constraint on `PARKED` sessions | — |
| D19 | 2026-09-13 | DRF `NUM_PROXIES` comes from `TRUSTED_PROXY_COUNT`: 0 natively, 1 in Compose behind Caddy | Unset, DRF trusted client-sent `X-Forwarded-For`, so each forged IP got a fresh 10/minute login budget (independent review finding, regression test added). Using 0 behind Caddy would pool every user into one bucket and let one attacker lock out all logins | Another proxy or load balancer sits in front of Caddy |
| D25 | 2026-09-14 | Opening a cash shift moves from M3 to M2; closing, counted cash and variance stay in M3 | Blueprint: every cash capture references the accepting operator's open shift. Capturing cash in M2 without one would need a backfill later | — |
| D26 | 2026-09-14 | Plates keep a display form (NFC, whitespace runs collapsed) and a matching key that also removes all whitespace and uppercases | Staff type "BA 12 PA 3456" and "ba12pa3456" for the same vehicle; the one-parked-visit-per-vehicle constraint (P03) must see them as one. Devanagari has no case, and NFC makes composed and decomposed forms equal | A plate format where spacing tells vehicles apart |
| D27 | 2026-09-14 | Location access is a `LocationAssignment` row per location and member, not an array on OrgMember. Owners act everywhere; other staff write only at assigned locations (`403 LOCATION_NOT_ASSIGNED`). Session reads stay organisation-wide | A foreign key keeps each location inside its organisation, a unique pair stops duplicates, and each assignment gets its own audit event. Managers and auditors read occupancy across locations | Staff must also be hidden from other locations' occupancy |
| D28 | 2026-09-14 | Session list and detail, quote, checkout, cash capture and exit are served by `billing`; routes stay under `/parking/sessions` and `/invoices` | The payment stage comes from invoices and payments, so a session read needs both. `billing` depends on `parking`, never the reverse | A reporting module takes over the reads |
| D29 | 2026-09-14 | Quote tokens are signed with `django.core.signing` and carry the cutoff; expiry (120 seconds) is checked against `clock.now()`, not `TimestampSigner` `max_age`. Checkout recalculates the fee from the pinned tariff, and a different total answers `QUOTE_INVALID` | `TimestampSigner` reads the real system time, so frozen-clock tests could not cover expiry. The browser never supplies an amount | — |
| D30 | 2026-09-14 | A cash capture must equal the full amount due (`409 AMOUNT_MISMATCH`); change is handled at the counter | M2 has no refunds, voids or split tender, so a partial or excess capture could not be corrected | Split tender, discounts or refunds arrive |
| D31 | 2026-09-14 | Exit is its own idempotent request after capture; there is no combined pay-and-exit endpoint | Each request makes one change under its own Idempotency-Key, so a timeout after payment retries only the exit and cannot take cash twice | POS measurements show the extra request slows the lane |
| D32 | 2026-09-14 | Idempotency keys are unique per organisation, actor, operation and key, and the stored payload hash also covers the organisation. Records expire after 7 days but are not purged until the worker exists (M4). Opening a cash shift takes no key | One user never replays another user's or another organisation's response, and a member of two organisations can reuse a key in each (independent review finding). A repeated shift open already answers `SHIFT_ALREADY_OPEN` through the one-open-shift constraint, and the screen refetches the current shift after any answer | Offline devices need per-device key series |
